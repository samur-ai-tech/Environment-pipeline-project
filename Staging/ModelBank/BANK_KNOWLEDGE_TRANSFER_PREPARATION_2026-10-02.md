## Production-guide contract after the current preview outcome

The practical guide should be a single path for the actual environment, not a menu of competing historical approaches:

1. Start from one versioned area source package and the latest integrated city HDA. Identify the exact catalog revision, Landscape material, and native DataTable used by that area.
2. Keep one per-AssetId source of bank decisions. Promote only exact assets for which package rights, intended use, model/material dependencies, geographic role, and visual choice have been decided. Preserve held rows and the separate building-module contract. Do not convert 380 preview candidates into a general release by bulk switch.
3. Persistently bind the reviewed DataTable to Geometry Input 0 of the area's HDA actor, set the area source and selected surface palette there, and save the actual area state. The current v013 authoring alone has not done this.
4. Have the same HDA produce geography and eligible nonbuilding `unreal_instance` outputs. Build complete architectural facades from compatible modules selected by stable building/segment identities, while keeping whole buildings and terrain materials in their proper lanes. The modular-building lane needs its missing connector, corner, residual and height contracts before it can be described as complete.
5. Keep the generated native content and named map, inspect the visible result in that map, and preserve the same asset identities when the area is regenerated or a second area is created. These are normal production continuity requirements, not separate disposable scenes.

This is the guide's structure, **not** a claim that every step already works. The saved v014 Developer map now supplies a concrete starting point: persistent table binding, selected Landscape layers, and preview-model placement. The production guide still needs the exact permanent-area setup and release/owner decisions, building completion, and ordinary repeatable area creation before it can describe an automatic finished bank workflow. The destination for a separate knowledge folder/project has not yet been selected, and no files have been transferred.

INTEGRATION DECISIONS
- Keep UpdateSky as the single final update path. Resolve current time/manual solar direction first, weather appearance next, then assign each owned component's final settings once. - Add exactly one owned VolumetricCloud component to the retained Blueprint. Use one dynamic material instance per actor, owned by that actor and recreated when necessary on construction/load. Reuse a valid instance during ordinary updates; never set parameters on a shared material instance or Material Parameter Collection. A small project-owned material instance can supply immutable defaults. Verify distinct actor ownership of the material without placing disposable actors/maps.
- Prefer installed /Engine/EngineSky/VolumetricClouds/m_SimpleVolumetricCloud and its resources. Their files are present. Actual graph inputs, units and parameter effects require assigned native inspection. If the engine parent lacks accessible coverage/wind controls, duplicate only the needed material into the package and expose parameters there. Do not edit the engine parent. No PWL/MW dependency is proposed unless a specific measured limitation justifies one.
- Cloud Amount: 0..1. Zero disables the owned cloud rendering contribution. One must produce visually continuous overcast using validated density/coverage parameters, not just increase opacity of scattered clouds. Tune sun attenuation, source-angle softness, cloud shadows and sky fill through UpdateSky. Avoid changing exposure automatically.
- Cloud Speed: labelled physical units after installed material coordinate/time units are established. Direction: degrees, with defined north relationship. Prefer material Time-driven advection so cloud animation does not need a Blueprint editor tick. Verify actual editor motion with realtime enabled; speed0 stops movement. If changing speed resets phase, correct with a retained phase offset rather than conceal a jump.
- Haze: use this actor's existing SkyAtmosphere Mie scattering/aerial perspective settings. Cache stable base values and compute from them each update; do not compound multiply. Do not modify the original map's ExponentialHeightFog_0 or its exposure.
- Weather Preset: Clear, Partly Cloudy, Overcast, Hazy, plus a defined custom-edit behavior. Apply only weather fields on deliberate preset selection; subsequent time edits must not reapply a preset and erase user's weather adjustments. Record last-applied preset or use an explicit Apply Preset action. Final UI choice to be verified in Details.
- Quality: Balanced and High modify only owned cloud component sample-count scales and appropriate owned light cloud-shadow settings. Installed UE5.8 has callable SetViewSampleCountScale, SetReflectionViewSampleCountScale, SetShadowViewSampleCountScale and SetShadowReflectionViewSampleCountScale. Do not change global scalability/cvars. Actual profile values and default will be chosen from measured original-scene results, not declared faster in advance.

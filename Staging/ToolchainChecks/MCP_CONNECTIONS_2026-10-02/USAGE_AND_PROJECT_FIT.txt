5. HOW EACH TOOL FAMILY HELPS OUR ACTUAL PROJECT

Houdini authoring — direct priority.
Use node discovery, parameter schemas, network inspection and connection tools to understand and version the city HDA. execute_code can support HOM operations not covered by a dedicated tool, including HDA PythonModule work, but must use the same versioned-authoring scope. Store HDA logic in its PythonModule, not hou.session. Geometry summaries can inspect counts, bounds, groups and attributes such as unreal_instance after an authorized cook. None of these tools validates a geographic package or model rights automatically.

Modular buildings — direct priority.
Houdini network/parameter tools can support reusable building rules. Existing Unreal StaticMeshTools can read bounds, slots, triangle/vertex counts and LOD information. This helps verify module dimensions and diagnose gaps, scale or material assignments. kks3800's six procedural primitive generators are generic authoring conveniences; they do not demonstrate a closed modular building, geographic footprint fitting, roofs or a believable city. The chosen module/rule system remains the starting point.

Materials and the surface palette — direct priority.
Existing Unreal MaterialTools and MaterialInstanceTools expose graph wiring, output inputs, material parameters and texture bindings. kks3800 adds graph analysis/build/batch functions and material previews. These can support MI_SurfaceBank_AllLayers and building material diagnosis. A compiled material or assigned texture is not proof that it looks correct on the Landscape/building; combine property readback with actual viewport evidence in a separately authorized task.

Shared model bank and catalog — direct priority.
Unreal asset discovery, dependencies/referencers and DataTable schema/row tools help reconcile the imported bank, native references and disabled selection data. Copilot's search/get_references/trace_reference_chain are useful for finding where a model or material is used. Catalog tools can inspect DT_NonBuildingBank_v3. They do not confirm persistent HDA input binding, rights, qualification or visible model placement merely because a row exists. Canonical RunEligible values remain false unless Aviv grants the exact release decision.

Unreal output, persistence and evidence — direct priority.
Actor/scene inspection, logs, screenshots and dirty-package readback support measured actor/component counts, exact map identity, material visibility and duplicate diagnosis. Named-save operations can later support approved persistence tasks. The official Houdini Engine API remains responsible for supported HDA instantiate/parameters/cook/Bake operations. Generic property tools may omit Houdini-specific inputs, bake settings or internal state; use supported official APIs/readbacks and do not infer missing values.

PCG — conditional, not an active substitute.
The registry offers PCG graph/node inspection and editing, which could assist a future explicitly chosen Unreal vegetation/details stage. Current selection/generation remains in the reusable Houdini route. Listing PCG tools does not authorize a second generator architecture or prove the installed graph operations on UE 5.8.

Blueprints — supporting priority.
Copilot can inspect hierarchy, references and graph structure; its skill runner includes native asset, editor, world and Blueprint editing primitives. kks3800 contains 111 Blueprint operations. These may support area controls or an explicitly required helper Blueprint. The current pipeline does not need a general gameplay system or a new manager/bridge merely because these APIs are available.

UI/widgets (109), Niagara (38), MetaSound/audio (26), behavior trees (51), blackboards (8), EQS (14), input (10) and project input mapping (1) are primarily gameplay, effects, interface or sound work. They may matter later for a playable/presentable environment, but do not resolve the geographic HDA, bank integration, building quality or regeneration gates.

6. RECOMMENDED TOOL SELECTION AND PRACTICAL EXAMPLES

First use the existing Unreal inspection tool for a task it already supports. Use Copilot when the gap is source/Blueprint/reference analysis or a documented native skill. Use kks3800 when its focused graph/material operation resolves a concrete supported-tool gap. Use houdini-mcp for Houdini authoring and inspection. Use official Houdini Engine for the geographic HDA connection/cook/Bake. Avoid multiple tools concurrently modifying the same asset or editor.

Houdini network inspection example: get_node_info(node_path=<reviewed node>, include_errors=true, force_cook=false), get_parameter_schema(node_path=<reviewed node>) and list_children(node_path=<reviewed root>). These inspect the actual target instead of guessing node names.
Copilot reference example: get_references(path='/Game/Project/Shared/SurfacePainting/MI_SurfaceBank_AllLayers', domain='asset', direction='both'). This is an example call shape, not a measured reference result.
kks3800 discovery example: search_unreal_tools(query='material', category='material', limit=10); describe_unreal_tools(names=['get_material_info','get_material_instance_parameters']); execute_unreal_tool(name=<chosen read operation>, params=<its returned schema>). describe accepts at most five names per call. Searching or describing does not execute the discovered operation.
Existing Unreal catalog example: describe DataTableTools, then use get_schema/list_rows/get_rows with the exact reflected DataTable reference. Existing Unreal inspection example: describe StaticMeshTools, then get_bounds/get_material_slots/get_triangle_count for the named mesh. Read schemas before supplying parameters; tool names alone do not guarantee argument formats.

7. OPERATIONS THAT NEED PARTICULAR CARE IN THIS PROJECT

The current documentation pass exports inventories and does not run scene mutations. Registered tools have differing side effects; prefixes like get, inspect or validate are not sufficient guarantees.
Houdini get_geo_summary explicitly cooks dirty geometry in the installed implementation. get_node_info can force a cook if force_cook=true. Rendering can evaluate/cook a graph. Do not use these during a zero-cook inspection without checking the actual behavior and target state.
Houdini load_scene/new_scene changes the active session; save_scene without a path saves the current file. Use explicit reviewed/versioned paths and resolve unsaved state.
Unreal save_assets([]) saves broadly; save_dirty_packages and save_directory are broad saves. Project rules forbid substituting them for a named reviewed save list. Generic delete/move/rename/batch fix operations must not reorganize the canonical bank by implication.
Material compile/fix, Blueprint compile, graph edit, LOD/Nanite/collision changes, direct actor spawn/delete and PCG edits can change editor/package state. One recorded editor owner controls such work and captures the result. City acceptance remains Aviv's decision.
